- **Zero Trust Model**: Never trust, always verify - especially important for modern environments
- **Shared Responsibility Model**: Understanding your vs. provider's responsibilities in cloud environments
- **Defense in Depth**: Layered security approach (Swiss cheese model)

## Module 2: Identity and Access Management (IAM)
**Estimated Study Time: 6-8 hours**

### Lessons Checklist
- [ ] 2.1 - IAM Key Concepts
- [ ] 2.2 - IAM Zero Trust Architecture
- [ ] 2.3 - IAM Capabilities
- [ ] 2.4 - End of Module Quiz

### Key Concepts to Master
- **Identity and Access Management (IAM)**: Managing digital identities and their access rights
- **Principle of Least Privilege (PoLP)**: Users get minimum access needed for their job
- **Segregation of Duties**: No single person controls an entire process (prevents fraud)
- **Authentication**: Proving who you are (something you know, have, or are)
- **Authorization**: Determining what authenticated users can do
- **Directory Services**: Centralized identity repositories (Active Directory, LDAP)
- **MFA/Multi-Factor Authentication**: Multiple verification methods for stronger security
- **Single Sign-On (SSO)**: One login for multiple applications
- **Role-Based Access Control (RBAC)**: Permissions based on job roles
- **Adaptive Authentication**: Dynamic authentication based on risk factors
- **Privileged Access Management (PAM)**: Securing high-risk admin accounts
- **Identity is the New Perimeter**: Shift from network-based to identity-based security

## Module 3: Network Security
**Estimated Study Time: 7-9 hours**

### Lessons Checklist
- [ ] 3.1 - Networking Key Concepts
- [ ] 3.2 - Networking Zero Trust Architecture
- [ ] 3.3 - Network Security Capabilities
- [ ] 3.4 - End of Module Quiz

### Key Concepts to Master
- **IP Addressing**: IPv4 and IPv6 address structure (192.168.1.1, etc.)
- **OSI Model**: 7 layers of networking (Physical, Data Link, Network, Transport, Session, Presentation, Application)
- **TCP vs UDP**: Reliable (TCP) vs. fast (UDP) protocols
- **Port Numbers**: 0-65535 range; well-known ports (HTTP:80, HTTPS:443, SSH:22, etc.)
- **Encryption in Transit and at Rest**: Data protection while moving and while stored
- **Network Segmentation**: Dividing networks into isolated zones with controlled access
- **Micro-Segmentation**: Granular network separation for zero trust
- **End-to-End Encryption**: Data encrypted from sender to recipient only
- **SASE (Secure Access Service Edge)**: Cloud-based security combined with networking
- **Firewalls**: Traditional, web application (WAF), and cloud security groups
- **Load Balancers**: Distribute traffic across multiple servers
- **Bastion Hosts**: Secure entry points to internal networks
- **VPNs**: Encrypted tunnels for secure remote access
- **DDoS Protection**: Defending against distributed denial of service attacks
- **Content Delivery Networks (CDN)**: Geographically distributed content and DDoS mitigation

## Module 4: Security Operations (SecOps)

### Lessons Checklist
- [ ] 4.1 - SecOps Key Concepts
- [ ] 4.2 - SecOps Zero Trust Architecture
- [ ] 4.3 - SecOps Capabilities

### Key Concepts to Master
- **Security Operations Center (SOC)**: 24/7 team monitoring for threats (your target role!)
- **Incident Response Team**: Specialized team responding to security breaches
- **Threat Hunting**: Proactively searching for hidden threats and vulnerabilities
- **Red Team/Blue Team**: Red simulates attacks; blue defends
- **NIST Cybersecurity Framework**: Five core functions (Identify, Protect, Detect, Respond, Recover)
- **Centralized Log Collection**: Aggregating logs from all sources for analysis
- **SIEM (Security Information and Event Management)**: Tool for log analysis and correlation
  - Log collection, data normalization, event correlation, alerting
  - User and Entity Behavior Analytics (UEBA)
  - Threat intelligence integration
- **XDR (Extended Detection and Response)**: Broader detection combining multiple data sources
  - Data integration from endpoints, network, cloud, email
  - Advanced analytics and automated threat detection
  - Unified investigation console
- **Continuous Monitoring**: Real-time threat detection and response
- **Threat Intelligence**: Staying informed about emerging threats and vulnerabilities
- **Security Automation**: Using tools to automate incident response and routine tasks
- **SOAR (Security Orchestration, Automation, and Response)**: Automating security workflows
- **Backup and Disaster Recovery**: Ensuring data availability and business continuity

## Module 5: Application Security (AppSec)
**Estimated Study Time: 6-7 hours**

### Lessons Checklist
- [ ] 5.1 - AppSec Key Concepts
- [ ] 5.2 - AppSec Key Capabilities
- [ ] 5.3 - End of Module Quiz

### Key Concepts to Master
- **Application Security (AppSec)**: Protecting software from vulnerabilities and attacks
- **Secure by Design**: Security integrated from the start, not added later
- **Input Validation**: Verifying all user inputs before processing
- **Output Encoding**: Properly formatting data sent to clients (prevents XSS)
- **Session Management**: Protecting user sessions from hijacking
- **Secure Dependencies**: Keeping libraries and components updated and patched
- **Error Handling and Logging**: Avoiding info leaks while maintaining audit trails
- **Secure Software Development Lifecycle (SDLC)**: Security in every development phase
- **SAST (Static Application Security Testing)**: Code analysis for vulnerabilities
- **DAST (Dynamic Application Security Testing)**: Testing running applications
- **IAST (Interactive Application Security Testing)**: Testing during runtime
- **RASP (Runtime Application Self-Protection)**: Real-time threat detection and response
- **Web Application Firewalls (WAF)**: Filtering malicious web traffic
- **Dependency Scanning**: Finding vulnerabilities in third-party libraries
- **Penetration Testing**: Simulating real attacks to find weaknesses
- **OWASP Top 10**: Most critical web application security risks
  - Injection, Broken Authentication, Sensitive Data Exposure, etc.
- **Container Security**: Securing containerized applications (Docker, Kubernetes)

### Key Concepts to Master
- **Data Security**: Protecting data from unauthorized access, disclosure, alteration, or destruction
- **Data Classification**: Categorizing data by sensitivity (public, internal, confidential, restricted)
- **Data Lifecycle Management**: Managing data from creation through deletion
  - Stages: creation, storage, processing, transmission, archival, disposal
- **Data Loss Prevention (DLP)**: Technologies to prevent unauthorized data sharing
  - Monitors data in motion, at rest, and in use
- **Encryption**: Converting data to unreadable format
  - At rest (stored data), in transit (moving data), in use (being processed)
- **Insider Risk Management**: Detecting and mitigating threats from insiders
- **Data Retention**: Policies for keeping and deleting data based on requirements
- **Personally Identifiable Information (PII)**: Special protection for personal data
- **Compliance**: Meeting regulatory requirements for data protection
  - GDPR, HIPAA, CCPA, PCI DSS, etc.
- **Data Governance**: Overall framework for managing organizational data

- [ ] 8.1 - AI Security Key Concepts
- [ ] 8.2 - AI Security Capabilities
- [ ] 8.3 - Responsible AI
- [ ] 8.4 - End of Module Quiz

### Key Concepts to Master
- **AI Security Unique Challenges**: Different from traditional cybersecurity
  - Data integrity and data poisoning attacks
  - Model security and reverse engineering
  - Adversarial attacks (imperceptible input changes)
  - Ethical considerations (bias, privacy, transparency)
- **Data Poisoning**: Manipulating training data to influence AI behavior
- **Adversarial Attacks**: Specially crafted inputs to fool AI systems
- **Model Evasion**: Exploiting weaknesses in AI decision-making
- **Prompt Injection**: Manipulating AI systems through specially crafted prompts
- **AI Red Teaming**: Testing AI systems for unique vulnerabilities
  - Broader than traditional red teaming
  - Tests for both malicious and benign failures
- **Counterfit**: Open-source tool for AI security testing
- **Responsible AI**: Ethical, transparent AI development
  - Fairness, accountability, robustness, transparency
  - Privacy protection and human oversight
- **AI Governance**: Frameworks and controls for responsible AI
- **Bias in AI**: Risks of training data bias affecting AI decisions
- **Explainability**: Understanding why AI systems make decisions (black box problem)

## Study Strategy Tips for IT Help Desk to SOC Analyst

1. **Leverage Your Current Role**: You already understand IT fundamentals—connect security to what you know
2. **Focus on Detection**: SOC analysts spend most time hunting and detecting threats—prioritize monitoring concepts
3. **Learn Tools Hands-On**: Don't just read about SIEM/XDR—get hands-on with free trials
4. **Understand the Human Side**: Insider threats and social engineering are often more effective than technical attacks
5. **Build a Home Lab**: Practice concepts with virtual machines and cloud free tiers
6. **Read Security News**: Follow CISA alerts, breach reports, and threat intelligence feeds
7. **Network with Others**: Attend security meetups and online communities
8. **Track Your Learning**: This document is your guide—update it regularly and celebrate progress!
